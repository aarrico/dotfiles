In code and scripts, keep comments to a minimum — only when completely necessary (e.g. a genuinely non-obvious decision or gotcha). Prefer self-explanatory code over explanatory comments.

**Why:** Stated directly during the dotfiles migration ("leave comments in the code or scripts to a minimum, only when completely necessary").
**How to apply:** Don't annotate obvious lines or restate what code does. No section-divider comment banners. Let naming and structure carry intent; reserve comments for the rare case where intent can't be expressed in code.
